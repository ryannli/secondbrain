RSS-first feed triage

A personalized feed should not become useless when a search API key is missing. RSS provides a reliable baseline because it needs no account, no billing setup, and no search quota. Search should expand coverage, not become the foundation that decides whether the product works at all.

The product should start with a small set of high-signal feeds and let the user replace them. Defaults should be opinionated enough to demonstrate the product, but not so broad that the feed becomes generic news.

The first-run experience should show the user three things quickly:
1. The system can gather candidates.
2. The system can explain why something is worth reading.
3. The user can capture a recommendation into the library.

Search keys can be introduced later, when the user understands why deeper coverage is valuable.
